# dsh-reload

DeepSeek Harness 插件：**热重载**已改动的插件，以及在需要时**重启客户端** —— 都不用手动关开 DSH。

> 状态：**已实现，客户端 UI 已验证。** 开发文档见 [docs/README.md](docs/README.md)（索引）。

## 这个插件解决什么

改完插件代码后，DSH 默认不会重新加载它：内置 HMR 只监听 profile 配置，
`link:` 开发包的源码改动不在它的监听范围内。结果是「改完代码 → 得重启 DSH 才生效」。

`dsh-reload` 提供一个显式的触发器：改完代码、构建完，点一下（或让智能体调一次工具），
DSH 重新加载所有文件有改动的插件 —— 不重启进程、不中断会话。

## 安装

```sh
dsh plugin --profile desktop add link:E:\Project\dsh-reload
```

桌面客户端也可以让 Agent 用 `plugin_manager` 的 `install_bundle`，target 传包目录的绝对路径。

装好后刷新一次页面，侧边栏底部和「设置 → 通用」最后一行就会出现入口。

## 两个动作

| 动作 | 效果 | 代价 |
|---|---|---|
| **热重载** | 重新加载文件有改动的插件 | 不碰进程、不丢会话；被重载插件的内存状态会清空 |
| **重启客户端** | 关闭并自动重新打开 DSH | 中断所有正在运行的任务 |

## 入口

| 入口 | 动作 |
|---|---|
| 侧边栏按钮（Settings 旁） | 点击 = 热重载（可在设置里隐藏） |
| 设置 → 通用 → 最后一行 | 两个按钮：热重载 / 重启客户端 |
| 智能体工具 `dsh_hot_reload` | 热重载（**智能体无法触发重启**） |

## 安全策略

**有任务在运行时，不允许重启客户端** —— 即使你手动确认也不会执行。

点击「重启客户端」时，DSH 会先检查是否有会话、后台任务或终端正在运行：
如果有，弹出一个**只读提示框**告知当前任务，**不提供重启选项**；
只有全部空闲时才进入确认框。这个判定在 Host 侧执行两次（点击前 + 执行前），
以防检查与执行之间刚好有新任务启动。

**热重载不需要确认** —— 它不碰进程、不杀任务、不丢会话。

## 与 `dsh-hot-reload` 的区别

npm 上已有一个 [dsh-hot-reload](https://www.npmjs.com/package/dsh-hot-reload)，
它监听 `pnpm-lock.yaml`，在**插件版本升级**时原地热重载。

本插件的触发场景不同：

| | dsh-hot-reload | dsh-reload |
|---|---|---|
| 触发条件 | 插件版本变化（lockfile 写入） | **显式触发**：点按钮 / 调工具 |
| 目标场景 | 升级已安装的插件 | **开发插件**：改源码、重新构建，但 profile 配置没变 |
| 是否含整机重启 | 否 | 是 |

两者解决的问题不重叠。

## 已知限制

- **热重载会清空被重载插件的内存状态**（包括本插件自己）。
- **替换版本加载失败时，旧代码不再运行**，插件变为 `failed`，直到文件修好后再热重载一次。
- **只改 `package.json` 不会被检测**（DSH 的官方限制）—— 需要重启客户端。
- **重启客户端会中断所有任务**，且没有失败兜底：新实例若未能启动，需要手动双击图标。
- 重启仅支持 **Windows 桌面客户端**；`dsh web` 场景下按钮会禁用并说明原因。
- 刚装好或刚更新插件后，**需要刷新一次页面**才能看到菜单入口（客户端模块图在页面加载时构建）。

## 开发

源码即产物，没有构建步骤。改完直接热重载即可生效。

```sh
# 工具 schema 与实现的字段一致性（用 Host 自己的断言函数）
ELECTRON_RUN_AS_NODE=1 "<DeepSeek Harness.exe>" --expose-internals scripts/check-schema.mjs

# 槽位组件不得依赖未声明的 props
node scripts/check-slot-components.mjs

# 声明与路径检查
node scripts/inspect-graph.mjs
```
