## 1. 目标与能力

### 1.1 两个动作

| 动作 | 实现 | 破坏性 | 谁能触发 |
|---|---|---|---|
| **热重载** | `ctx.hmr.runExclusive(() => ctx.hmr.reconcileProfile())` | 低（不碰进程） | 智能体工具 + UI |
| **重启客户端** | detached 外部重启器 → 结束 Electron 主进程 → 等锁释放 → 重新拉起 | **高**（中断所有任务） | **仅 UI** |

### 1.2 明确不做

| 不做 | 理由 |
|---|---|
| 智能体触发重启 | Host 是 Electron 主进程的子进程，智能体跑在 Host 里——杀主进程 = 杀自己，响应必丢 |
| 页面刷新（`location.reload()`） | client bundle 由 `dsh-client-hmr` 轮询自行替换；Host release 变化时页面自己会提示 |
| 源码目录监听 | 「代码改完了」是语义判断，文件系统判断不了；误触发会让插件变 `failed` 且不可逆 |
| 防抖 / 静默窗 | 没有监听就没有这个问题 |
| 重启失败兜底 / 回滚 | 第一版不做 |
| 修改 profile 配置 | 零配置改动，不动 `hmr`、不动 `root` |

### 1.3 术语

| 术语 | 含义 |
|---|---|
| **热重载** | 不碰进程，把「磁盘上文件变过的插件」停掉、重新 import、重新 apply |
| **在飞任务** | 正在跑的 agent turn / 排队中的 inbox 消息 / 运行中的 job / 打开的 terminal |
| **`link:` 包** | 用 `dsh plugin add link:<路径>` 装的开发中插件 |

## 2. 架构

```
┌────────────────────────── Client（浏览器） ──────────────────────────┐
│  conversation.header.leading  主区域顶栏最左侧「热重载」               │
│  sidebar.footer.action        侧边栏底部：展开带文字，折叠只留图标      │
│  shell.overlay                右下角悬浮按钮                          │
│  sidebar.panellist.actions    「更多」菜单最下一行「热重载」            │
│  plugins.bundle.config        插件详情页卡片：两个按钮 + 三个显示开关    │
│  settings.action              设置面板顶栏右侧（Close 左）两个紧凑按钮   │
│         │                                                            │
│         ├─ 热重载 → POST /api/dsh-reload/hot-reload   （直接执行）   │
│         └─ 重启   → GET  /api/dsh-reload/status                     │
│                       ├─ 有在飞任务 → 提示框（只读，无重启按钮）      │
│                       └─ 无在飞任务 → 确认框 → POST /restart         │
└─────────┼────────────────────────────────────────────────────────────┘
          │
┌─────────▼──────────────────── Host ──────────────────────────────────┐
│  路由双挂：connection.fetch（桌面版）+ webServer（Web 版兜底）        │
│                                                                      │
│  hotReload()   ← 唯一实现，工具与 UI 共用                             │
│    hmr.runExclusive(() => hmr.reconcileProfile())                    │
│                                                                      │
│  inspectActivity()  ← 返回在飞任务清单（复用 hasDesktopActiveTasks 判据）│
│                                                                      │
│  restart()     ← 唯一实现，仅 UI 可达                                 │
│    1. 再查一次在飞任务（权威判断，防 TOCTOU）                          │
│    2. 有任务 → 409 + 清单，拒绝执行                                    │
│    3. 无任务 → 写 state.json(pendingRestart)                          │
│              → spawn(detached) 启动 restarter                        │
│              → 立即返回（响应先落地）                                  │
│    4. restarter 等 1.2s → 杀主进程 → 等消失 → 剥离 ELECTRON_RUN_AS_NODE│
│              → 拉起新实例 → 存活探测（约 2s）→ 失败则重试 3 次         │
│                                                                      │
│  ctx.tools.register('dsh_hot_reload')  ← 只调 hotReload()             │
└──────────────────────────────────────────────────────────────────────┘
```

**「设置 → 通用」里没有本插件的任何内容。** 通用页是全局偏好的座位（语言、主题、
输入框回车行为），热重载 / 重启是**本插件自己的动作**，放在那里语义不对。

**六个入口的分工**（前四个各有一个独立开关，见 §6.3）：

| 入口 | 槽位 | scope | 语境 | 为什么需要 |
|---|---|---|---|---|
| 主区域顶栏最左 | `conversation.header.leading` | root | 一直在视野里 | **侧边栏折叠时的兜底**：Windows 折叠会隐藏整个 `footArea` |
| 侧边栏底部 | `sidebar.footer.action` | root | 随手触发 | 最快，但 Windows 折叠后不可见（§6.2） |
| 右下角悬浮 | `shell.overlay` | root | 任何界面 | 右下角通常空着；不受折叠/布局影响 |
| 「更多」菜单 | `sidebar.panellist.actions` | root | 找功能时 | 用户「想找个开关」时的自然落点 |
| 插件详情页卡片 | `plugins.bundle.config` | root (keyed) | 本插件主页 | 三个开关 + 两个按钮 |
| 设置面板顶栏 | `settings.action` | root | 打开设置时 | 重启客户端只有这里有 |

`plugins.bundle.config` 的 `key` 必须等于包名 `dsh-reload`
（详见 [02-平台事实.md §4.3.1](02-平台事实.md)）。

**设计原则**：

- `hotReload()` 与 `restart()` 各只有**一个实现**，工具与 UI 共用，不维护两套逻辑。
- 重启的**权限判定在 Host 侧**，不信任前端传参。
- 判据复用桌面壳自己的 `hasDesktopActiveTasks`，避免「DSH 认为没事、插件认为有事」。

## 3. 行为规格

### 3.1 热重载

| 触发者 | 行为 |
|---|---|
| 智能体工具 `dsh_hot_reload` | 立即同步执行，返回真实结果 |
| 侧边栏按钮 | 点击立即执行，**不弹任何框**，结果走 toast |
| 设置页「热重载」按钮 | 同上 |

无确认框——热重载不碰进程、不杀任务、不丢会话。

### 3.2 重启客户端（核心：安全优先）

**两步判定，Host 侧权威**：

```
用户点「重启」
  ↓
前端 GET /api/dsh-reload/status
  ├─ active = true  → 提示框（只读，见 §3.3），流程结束
  └─ active = false → 确认框 → 用户点「重启」
                        ↓
                     POST /api/dsh-reload/restart
                        ↓
                     Host 再查一次在飞任务（防 TOCTOU）
                       ├─ 有任务 → 409 + 清单 → 前端改用提示框展示
                       └─ 无任务 → 执行重启
```

**关键规则**：只要有在飞任务，**即使用户确认也不会执行重启**。安全优先级高于用户意志。

### 3.3 两个框的区分

| 场景 | 框的类型 | 按钮 | 语义 |
|---|---|---|---|
| **有在飞任务** | **提示框** | 只有「知道了」 | 告知，**没有重启选项** |
| **无在飞任务** | **确认框** | 「重启客户端」/「取消」 | 危险操作二次确认 |

**提示框内容**：

```
现在无法重启

有任务正在运行，重启会中断它们。请等待任务结束后再试。

  会话  「重构登录模块」                      运行中
  任务  pnpm build                             运行中
  终端  dev server                             打开中

                                          [ 知道了 ]
```

**确认框内容**：

```
重启客户端？

DSH 会关闭并自动重新打开。当前没有任务在运行。
重启期间页面会短暂断开，完成后需要重新加载。

                              [ 取消 ]  [ 重启客户端 ]
```

### 3.4 侧边栏按钮

| 交互 | 行为 |
|---|---|
| 点击 | 热重载（不弹框） |
| 悬停 | tooltip「热重载」 |
| 长按 | **无特殊行为**（不做长按重启） |

## 4. 接口规格

### 4.1 工具 `dsh_hot_reload`

**参数**：无（`type: 'object'`，`properties: {}`）

**输出**：

```json
{
  "applied": true,
  "changed": true,
  "replaced": [{ "id": "include:reload", "name": "dsh-reload" }],
  "replacedPlugins": ["dsh-reload"],
  "pending": [{ "url": "file:///...", "reason": "host-module" }],
  "restartReason": null,
  "warnings": [],
  "notes": []
}
```

| 字段 | 说明 |
|---|---|
| `applied` | 操作是否成功完成 |
| `changed` | 是否真有 Loader 条目被替换（`false` = 磁盘无变化，正常非错误） |
| `replaced` | 被替换的条目（`id` + 包名） |
| `replacedPlugins` | 被替换的包名（从 `replaced` 投影，便于阅读） |
| `pending` | 需整机重启才生效的模块 |
| `restartReason` | `module-comparison` / `package-moved` / null |
| `warnings` | `reconcileProfile` 原始诊断 |
| `notes` | 把 `pending` / `restartReason` 翻成可读中文句子 |

**工具描述要点**：热重载不重启客户端、不中断会话；`pending` 非空需如实告知用户要重启客户端；`changed:false` 不是错误。

### 4.2 HTTP 路由

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/dsh-reload/ping` | 探活 → `{ ok:true, version }` |
| `GET` | `/api/dsh-reload/status` | 在飞任务 + 能否重启 |
| `POST` | `/api/dsh-reload/hot-reload` | 热重载 → 同工具输出 |
| `POST` | `/api/dsh-reload/restart` | 重启；有任务时 409 + 清单 |
| `POST` | `/api/dsh-reload/pending-restart` | 取出并清除「刚重启过」标记 |

**双挂**：`connection.fetch.register`（桌面版主通道）+ `webServer.register({kind:'prefix'})`（Web 兜底）。
Web 兜底用 `ctx.connection.requestRejection(req)` 做同源校验 → 403。

### 4.3 在飞任务的数据结构

```ts
{
  active: boolean,
  agents:    [{ id: string, title: string | null, status: 'running' | 'queued' }],
  jobs:      [{ id: string, label: string, status: string }],
  terminals: [{ id: string, title: string }],
  counts: { agents: number, jobs: number, terminals: number }  // 未截断总数
}
```

- 每类最多列 3 条（`MAX_PER_KIND`），`counts` 给 UI 显示「等 N 个」
- `agents`：`ctx.agents.list()` 过滤 `status === 'running'` 或 inbox 非空
- `jobs`：`ctx.jobs.list()` 过滤 `running` / `stopping`；`undefined` caller 也查（覆盖全局 job）
- `terminals`：`ctx.terminals.list()`

### 4.4 落盘

| 项 | 规格 |
|---|---|
| 路径 | `$DSH_HOME/dsh-reload/state.json` |
| 内容 | `{ version:1, lastHotReload: { at, result } \| null, pendingRestart: { at, reason } \| null }` |
| 写入 | 原子写（`.tmp` + rename） |
| 用途 | UI 显示上次结果；`pendingRestart` 标记「正在重启」，新实例读到后提示一次并清除 |

为什么必须落盘而不是放内存：热重载会把本插件自己的 Loader entry 停掉再重新 import，内存状态随之清零。

## 5. 重启实现

### 5.1 restarter 的启动

进程树**不在** job object 内（证据见 [02-平台事实.md](02-平台事实.md)），所以普通 `spawn({ detached: true })` 即可，
不需要 WMI / PowerShell。

```js
const child = spawn(nodeExe, [restarterPath, configPath], {
  detached: true,
  stdio: 'ignore',
  windowsHide: true,
})
child.unref()
```

- 参数走**独立的 JSON 配置文件**而不是命令行：Windows 路径含空格与反斜杠，命令行转义极易出错
- `stdio: 'ignore'`：父进程死后不会因写管道失败而崩溃

### 5.2 restarter 的步骤

```
1. 等 1.2s            让 HTTP 响应先落地
2. taskkill /PID /F   结束主进程
3. 轮询直到消失        不用固定 sleep —— 单实例锁的时序全靠这一步
4. 清理残留子进程      卡死的 Host 会变孤儿并占端口
5. 等 1.2s            释放单实例锁
6. 剥离环境变量       删掉 ELECTRON_RUN_AS_NODE（否则新实例变纯 Node 秒退）
7. spawn(exe)         拉起新实例
8. 存活探测           约 2s 后仍在才算成功；失败则重试（最多 3 次）
```

**第 3 步是唯一保障**：`requestSingleInstanceLock()` 失败时 Electron 直接 `quit()`。
新实例启动太早会**静默退出**，用户看到的是「DSH 关了，再也没起来」。

**第 6 步是「关了不重开」的根因修复**：Host 环境里带着 `ELECTRON_RUN_AS_NODE=1`，
原样传给新实例会让 Electron 以纯 Node 模式运行、不建窗口并立刻以 0 退出。
详见 [02-平台事实.md §3.2.1](02-平台事实.md)。

**第 8 步为什么必要**：上面两种失败（锁未释放、环境变量残留）都是**静默的**——
`spawn()` 不报错、退出码是 0。只观察进程是否存活才能区分「起来了」和「起来后秒退」。

**第 4 步为什么必要**：正常情况 Host 收到 IPC `disconnect` 会主动 shutdown，
但卡死的 Host 会留下孤儿占着端口，导致新实例启动失败。清理时**不带 `taskkill /T`**——那会把还没启动的新实例也带走。

### 5.3 定位主进程与安全校验

```js
const mainPid = process.ppid     // 实测等于 Electron 主进程 PID
const exe = process.execPath     // 实测等于桌面 exe
```

三道闸，任一不过就拒绝重启：

1. 平台必须是 Windows（其余平台明确拒绝，避免「按钮能点但一定失败」）
2. 可执行文件存在、可执行，且 basename 匹配 `/deepseek[ -]?harness(\.exe)?$/i`
3. 主进程 cmdline 不含 `--type=`（排除 GPU / renderer / utility 子进程）

**为什么不 `app.relaunch()`**：插件拿不到 Electron 主进程的 `app` 对象，`DESKTOP_IPC` 也没有 restart 通道。

## 6. UI 规格

### 6.1 槽位

| 槽位 | kind | 注册身份 | owner props |
|---|---|---|---|
| `sidebar.footer.action` | list | `id: 'dsh-reload:button'`, `order: 10` | `{ wide: boolean }` |
| `plugins.bundle.config` | keyed | `key: 'dsh-reload'`（= 包名） | `{ view: 'summary' \| 'page', form? }` |
| `settings.action` | list | `id: 'dsh-reload:header-actions'`, `order: 10` | （空） |
| `conversation.header.leading` | single | 无 id（single 槽位） | （空） |
| `shell.overlay` | list | `id: 'dsh-reload:floating'`, `order: 900` | （无） |
| `sidebar.panellist.actions` | list | `id: 'dsh-reload:more-menu'`, `order: 100` | `{ entries, onOpen, onPinnedChange, onDismiss }` |

六者都通过 `ctx.slots.inject(slot, () => ctx.slots.register({ ..., locale: NS }, Component))` 注册。
`locale: NS` 让框架把翻译函数 `t` 注入组件 props。

> `plugins.bundle.config` 的 `key` **必须精确等于包名**：插件管理页用
> `ledger.bundles.has(pkg.name)` 决定是否渲染这一段，而那个集合就是该槽位注册过的
> key。写成 Loader entry id（`reload` / `include:reload`）会**静默不显示**。

> **不再注册 `settings.general.item`**。「设置 → 通用」里不留本插件的任何内容。

### 6.2 侧边栏按钮

- **展开时（`wide: true`）：图标 + 文字「热重载」**。尺寸照抄宿主 Settings 触发器
  （`ui-settings-general` 的 `.trigger`：42px 高、14px 字号、`radius-md`、
  `padding: 0 10px 0 8px`、hover 用 `interactive-bg-hover`），
  这样两行看起来是同一控件家族，而不是「一个光秃秃的图标」。
- 折叠时（`wide: false`，36/56px 竖排）：只留图标 + `aria-label`（没有横向空间放字）。
- 图标：循环箭头（`currentColor` 自绘 SVG），重载中旋转
- 点击 → 热重载，不弹框
- 可在插件页里隐藏（`localStorage` 偏好，立即生效）

> ⚠️ **已知缺陷（宿主行为，插件无法修复）**：`SidebarRoot` 里
> `wide = windowsTitlebar ? !collapsed : !collapsed || !settled`，而 CSS 有
> `[data-windows-titlebar] .collapsed .footArea { display: none }`。
> 所以 **Windows 上侧边栏一折叠，`sidebar.footer.action` 整块消失**；
> `shell.leading` 又只在 `darwin && sidebarCollapsed` 挂载，Windows 折叠后没有替代座位。
> 这正是「主区域顶栏」「右下角悬浮」「设置面板顶栏」这三个入口存在的理由。

### 6.2.1 主区域顶栏按钮

槽位 `conversation.header.leading`：主区域顶栏**最左侧**，会话标题左边，
无会话时也在（root scope，`replaceRisk: none`）。

尺寸约束来自宿主 `ConversationRoot`：
`.header` 是 grid（`auto minmax(0,1fr)`），`.headerLeading` 是 `flex:none; gap:8px`。
所以按钮做 28px 高、13px 字号、无边框、hover 底色 —— 与顶栏其他图标按钮同族，
不会把会话标题挤走。

### 6.2.2 右下角悬浮按钮

槽位 `shell.overlay`：整窗浮层，宿主说明明确鼓励这类用途
（「a badge, a toast stack or a status pill all belong here」）。

- 定位 `position: fixed; right: 24px; bottom: 24px`，圆角胶囊 + 阴影
- **必须自己 `pointer-events: auto`**：该层默认 `pointer-events: none`
  （设计上不挡底下界面），不写回来就点不到
- 右下角在多数界面是空的（对话流靠左、输入框居中偏下）

### 6.2.3 「更多」菜单里的一行

槽位 `sidebar.panellist.actions`：侧边栏「更多」展开菜单的行。
宿主自己的 `entry-customization` 在这里渲染「浏览更多插件」「创建你的插件」两行，
本插件排在它们之后（`order: 100`）。

**自绘菜单行**（官方规则禁止 require 宿主 primitives 包，`MenuItemButton` 在那里）：
高度 32px、图标 16px、字号 14px、`radius-md`、hover 用 `interactive-bg-hover`，
与宿主 `MenuItemButton` 视觉一致。点击时**先 `onDismiss()` 关菜单**再执行——
菜单是 portal 浮层，不关会一直压着界面。

### 6.3 插件详情页卡片

位置：「设置 → 插件」→ 已安装 → 热重载（dsh-reload）详情页，在插件描述与组件行之间。

```
┌─────────────────────────────────────────────────────────────────┐
│ 热重载                                                          │
│ 重新加载文件有改动的插件，不中断会话。                          │
│                                                                 │
│ [⟳ 热重载]  [重启客户端]                                        │
│ ─────────────────────────────────────────────────────────────── │
│ 在侧边栏显示热重载按钮                               [开关]     │
│ 关闭后只隐藏侧边栏底部那个按钮，本页和设置顶栏的按钮不受影响。  │
│ ─────────────────────────────────────────────────────────────── │
│ 在主区域顶栏显示热重载按钮                           [开关]     │
│ 顶栏最左侧（会话标题左边）。侧边栏折叠时它仍然在。              │
│ ─────────────────────────────────────────────────────────────── │
│ 在右下角显示悬浮按钮                                 [开关]     │
│ 固定浮在窗口右下角，任何界面都能点到。                          │
└─────────────────────────────────────────────────────────────────┘
```

- 三个开关各存一个 `localStorage` 键，立即生效、不触发重载
- 只存过 `'0'` 才算关闭；首次安装 / 读不到都按**显示**处理（`readPref()`）
- 「重启客户端」用危险色（`--dsw-alias-state-error-primary`）
- 执行中：按钮 disabled + 「重载中…」
- 结果：toast（成功 / 无变化 / 失败）；`notes` 非空时用错误色延长展示
- 有 `pending` 时在描述下方显示「N 个模块需重启客户端才生效」

### 6.4 设置面板顶栏按钮

槽位 `settings.action`，宿主渲染在 `.content > .header > .actions`
（`justify-content: flex-end`，顶栏高 54px，`padding: 20px 14px 8px 10px`，Close 28×28）。

```
┌──────────────────────────────────────────────────────────────┐
│                                    [⟳ 热重载] [重启客户端] [×] │
└──────────────────────────────────────────────────────────────┘
```

- **紧凑尺寸**：28px 高、12px 字号，保证不撑高顶栏、不跟 Close 抢注意力
- 该槽位是 **root scope，任何设置页都渲染**（不只是「账户与余额」）
- 选择它而非「自绘浮动条 + DOM 定位」：后者要依赖宿主 CSS 类名与结构，
  DSH 升级后会静默失效；官方槽位零 hack

### 6.4 两个框

自绘 Modal（不 require 宿主 primitives），`role="dialog"` + `aria-modal`，Esc 关闭，初始焦点落在主按钮：

- **提示框**（有任务）：只有「知道了」
- **确认框**（无任务）：「取消」/「重启客户端」

样式只引用 `--dsw-alias-*` token。

### 6.5 重启期间的界面锁定

杀掉主进程前约 1.2 秒内窗口仍可交互，必须封锁全部操作。
**锁定在「点击瞬间」开始**，不能等 HTTP 200 回来——往返期间用户完全可能再点一次。

| # | 动作 | 目的 |
|---|---|---|
| 1 | 立刻 `restarting = true` | 状态锁先于网络请求 |
| 2 | 全屏遮罩「正在重启 DSH…」+ `pointer-events` 全捕获 | 挡住所有点击 |
| 3 | 遮罩不可关闭（无按钮、忽略 Esc、忽略点外部） | 防手滑解除 |
| 4 | 所有按钮 disabled（含侧边栏按钮） | 双保险 |
| 5 | 重复点击直接 return | 幂等 |

**遮罩挂 `document.body` 而不是走 React 槽位**：重启按钮在设置面板里，设置面板 z-index 实测 1000–1100。
走槽位渲染的遮罩会被困在槽位的层叠上下文内、**盖不住设置面板**，用户仍能操作其他控件。

**遮罩的视觉构成**：

```
┌──────────────────────────────────────────────────────────────┐
│                    （整屏半透明遮罩 + 模糊）                   │
│                                                              │
│                 ┌────────────────────────┐                   │
│                 │          ◠             │  ← 转圈指示器      │
│                 │   正在重启 DSH…         │  ← 标题           │
│                 │ 窗口即将关闭，稍后会自动   │  ← 副标题         │
│                 │ 重新打开。              │                   │
│                 └────────────────────────┘                   │
└──────────────────────────────────────────────────────────────┘
```

| 元素 | 样式要点 |
|---|---|
| 遮罩底 | `background: var(--dsw-alias-bg-mask-1)` + `backdrop-filter: blur(3px)` |
| 中央卡片 | `.dshr-lock-card`：`--dsw-alias-bg-overlay` 底 + 边框 + 阴影 |
| 转圈 | `.dshr-lock-spinner`：22px 圆环，`border-top-color: brand-primary` |

> ⚠️ **不要用 `--dsw-alias-bg-base` 当遮罩色**。它的语义是「不透明的应用底色」，
> 跟页面背景同色，盖上去等于没盖——这就是「点了重启但看不到蒙版」的原因。
> 遮罩色要用 `--dsw-alias-bg-mask-*`（深色 `#00000080`、浅色 `#0000003d`）。

### 6.6 锁定解除（必须配对）

只有「重启真的会发生」才保持锁定，否则 UI 会永久冻结：

| Host 返回 | 前端行为 |
|---|---|
| `200` | **保持锁定**，等窗口消失 |
| `409`（在飞任务冒出来了） | **立刻解锁** → 改显示提示框 |
| `403` / `500` / 网络错误 | **立刻解锁** → toast 报错 |

**超时自动解锁**：锁定后 8 秒若页面仍存活，自动解锁并 toast「重启似乎没有生效，请重试或手动重开 DSH」。
这不是失败兜底（不回滚、不写诊断），只是一层防止界面冻结的保护。

### 6.7 用户可见时间线

| 时刻 | 发生什么 | 用户看到 |
|---|---|---|
| t=0 | 点「重启客户端」 | 按钮变灰、遮罩升起 |
| t≈50ms | Host 返回 200 | 遮罩「正在重启 DSH…」 |
| **t≈1.2s** | 杀掉主进程 | **整个窗口消失** |
| t≈1.2–2.7s | 桌面空白 | 什么都没有（约 1.5 秒） |
| t≈2.7s | 新实例启动 | **新窗口出现**，加载首页 |
| t≈3s | 读到 `pendingRestart` 标记 | toast「DSH 已重启」 |

**不做**轮询 `/ping` 或自动 `location.reload()`：页面在主进程被杀时已随窗口消失，
不存在「一个还活着的页面在等新实例」。

### 6.8 「刚重启过」提示的位置

`pending-restart` 的读取放在 `apply()` 里，而不是卡片组件里：卡片只在用户打开插件
详情页时才挂载，而这条提示应该在应用启动后就出现、且只出现一次。

### 6.9 toast 的位置

所有 toast（「没有检测到改动」「已热重载 N 个插件」「重启失败」等）统一显示在
**顶部居中**：

```css
top: calc(var(--dsh-frame-chrome-top, 0px) + 16px);
```

底部会跟输入框、状态栏挤在一起；`--dsh-frame-chrome-top` 是宿主的窗口标题栏
高度变量（设置面板的 mask 也用它），加上它才不会被标题栏压住。

## 7. 错误与边界矩阵

| 情况 | 行为 |
|---|---|
| `ctx.hmr` 不存在 | 工具 `isError`「当前 profile 未启用热重载」；UI 按钮 disabled |
| `reconcileProfile` 抛错 | `applied:false` + 错误消息；红字显示；写 state.json |
| 替换版本加载失败 → 插件 `failed` | 说明「插件 X 加载失败，旧版本已停止；修好后再次热重载即可恢复」 |
| `pending` 非空 | 正常返回，UI 显示「N 个模块需重启客户端才生效」 |
| 并发热重载 | `runExclusive` 天然串行，后到排队 |
| 热重载替换本插件自己 | 结果落盘，UI 轮询拿到；工具响应可能丢（罕见） |
| **重启时有在飞任务** | **拒绝执行**，返回 409 + 清单，前端转提示框 |
| 非桌面环境（`dsh web`） | 重启按钮 disabled，提示「仅桌面客户端支持」 |
| exe 名不匹配 / ppid 是子进程 | 拒绝重启，返回具体原因 |
| **新实例拉起后秒退**（锁未释放 / 环境变量残留） | restarter 做存活探测，重试最多 3 次；仍失败则记日志报错，前端 8s 超时解锁并提示手动重开 |
| 重启请求失败（409/500/网络） | 前端**立刻解锁**并 toast 报错 |
| 锁定时页面仍存活超 8s | 自动解锁 + toast「重启似乎没有生效」 |
| 遮罩看不见 | **已修复**：遮罩色必须用 `--dsw-alias-bg-mask-*`，不能用 `--dsw-alias-bg-base` |
| 写 state.json 失败 | 不阻断；console.warn |

## 9. 已确认决策

| 项 | 决策 |
|---|---|
| 包名 | **`dsh-reload`** |
| 工具名 | `dsh_hot_reload` |
| `/reload` 斜杠命令 | ❌ 不加（智能体用不了斜杠命令） |
| 侧边栏按钮显示 | 始终显示，但可在设置里用开关隐藏（localStorage，立即生效） |
| 侧边栏交互 | 点击 = 热重载；**不做长按重启** |
| 热重载确认框 | ❌ 不加 |
| 重启确认框 | ✅ 有（无任务时） |
| 有任务时点重启 | **提示框，只读，禁止重启**（Host 侧二次校验，防 TOCTOU） |
| 重启期间锁定 | ✅ 点击瞬间即锁，全屏遮罩挂 `document.body`，失败/超时自动解锁 |
| 重启后提示 | ✅ 读 `pendingRestart` 标记 → toast「DSH 已重启」 |
| 重启失败兜底 | ❌ 第一版不做 |
| 源码监听 / 静默窗 | ❌ 不做 |

取舍过程见 [04-决策记录.md](04-决策记录.md)。
